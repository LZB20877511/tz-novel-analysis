# TZ小说分析 · 标准作业流程（SOP v2.0）

> 本文件是**流程的唯一权威**。角色卡（`agents\*.md`）定义"你是什么角色"，
> 本文件定义"按什么顺序做、什么时候跑什么工具、在哪一步卡闸门"。
> v2.0 依据**五本实战复盘**（《史上第一祖师爷》《寸芒》《弹痕》《大王饶命》…）改写。

---

## 0. 一页速览

```
[1] 派单声明
     ↓
[2] 取证（并行）：book-scout（定位+全文） ‖ review-miner（外部共识）
     ↓
[3] 切分 + 三区间实读（并行）：reader-early / reader-mid / reader-late
     ↓
[4] model-critic：先自评（落盘）→ 后对照（落盘）
     ↓
[5] Lead 汇总草稿
     ↓
[6] ⚙️ 跑 scripts\precheck.py  ← 程序闸门（新增，省一轮往返）
     ↓
[7] spoiler-guard 审校  ← 语义闸门
     ↓
[8] Lead 照改 → 重跑 precheck --mode final → 发布
     ↓
[9] 落盘 + 追加跨书基线
```

**两条铁律不变**：① 事实不许编、评价必须给；② 覆盖度必须披露、防剧透零容忍。

## 1. 派单声明（30 秒，别跳过）

```
🎯 任务分配声明
- 模式：单书分析 / 偏好推荐 / 对比 / 追问
- 实体：书名（含消歧结论）
- 派单：book-scout / chapter-reader×N(区间) / review-miner / model-critic / spoiler-guard
- 评价双轨：model-critic 自评（主）+ review-miner 外部共识（对照）
- 抽样策略：开头[a-b] 中段[c-d] 尾段[e-f]
- 已知限制：网文？VIP墙？字体加密？
```

## 2. 取证阶段（并行，别串行等）

### 2.1 book-scout：**消歧是第一要务**

五本里有四本出现过消歧问题，且**都是同一几类**：

| 坑 | 实例 | 判别法 |
|---|---|---|
| 书名少字 | 《史上第一祖师》实为《史上第一祖师**爷**》 | 搜索相关性第 1 位 + 简介互证 |
| **改编条目反超原著** | 《大王饶命》动画 7.3/**6597 人** vs 小说第 1 卷 7.2/1199 人（**5.5 倍**） | 看条目分类是"图书"还是"影视"；**人数异常高要警惕** |
| **系列作其实是实体分册** | 「大王饶命2」= 第 2 册（ISBN+页数+丛书 13 册），**不是续集** | **给 ISBN/页数 = 纸质分册，非独立网文** |
| 同名异书 | 孙汝春《弹痕》也是 7.9（42 人），与纷舞妖姬版无关 | 比对**评分人数**，不可互证 |
| 作者笔名撞词 | 起点 5 本书的作者叫「弹痕遍地」 | 看结果里是书名命中还是作者命中 |
| 目录混入作者话 | 《大王饶命》1363 条 = 1329 正文 + 3 番外 + **31 条作者话** | **"目录条目数=章数"必高估** |

**交付物**（缺一条 reader 就没法开工）：
- bookId、总章数、免费/VIP 分界、分卷结构
- 某转载站 bookId、**缺失章号**、可读页面数
- **5 个关键样本完整 URL**（第1章/25%/50%/75%/末章）
- **三区间逐章 seq + URL**（供三个 reader，区间不得重叠）
- 抽 2 章实测 `chars / pua / latin`

### 2.2 缺章判定：走三步法（见 `agents\chapter-reader.md`）
1. **1..N 连号核验** → 连续即"无缺章"，收工；
2. 有缺口 → **pageId 断号探查**：连号=章号标注错，断号=真缺页；
3. 才判"真缺章"，报告里**必须区分"真缺章"与"站点标注 bug"**。

### 2.3 编码验收：**pua 低 ≠ 正文干净**（2026-10 事故，会整章报废）

**事故**：`fetch_shuquge_v4.ps1` 原用「UTF-8 严格模式，遇非法字节抛异常 → 整体回退 gb18030」。
《神游》页面只要混入 **1 个**非法字节，整章就被当 GBK 解码 → **seq1、seq4 整章乱码（32/32 段、62/63 段全废）**。

**危险之处**：乱码章的 **pua 只报 5.2%**。按「pua > 50 才判字体加密」的旧阈值，会被误判成**"轻度污染、基本可用"**，实际**整章不可用**。

**正确策略（已写入 v4）**：
```
1) 先用【宽松 UTF-8】解码（UTF8Encoding($false,$false)）
2) 统计替换符 U+FFFD 占比
3) 占比 > 2% 才试 gb18030，并比较两者谁更干净
4) 绝不"抛异常就整体换编码"
```

**reader 验收要求**（比 pua 阈值可靠）：
- **pua 低 ≠ 正文干净**，必须**同时看 U+FFFD 替换符数**。
- 抽验首行是否可读中文；出现 `��` / `锟斤拷` / 连续乱码 → **判该章不可用，重抓**。
- 修复后实测：seq1 → 5959 字、pua=0、U+FFFD=2；seq4 → 6312 字、pua=0、U+FFFD=2（正文完整）。

> 三类"脏文本"必须分清，处理方式完全不同：
> | 类型 | 指标 | 是不是作者问题 |
> |---|---|---|
> | **PUA 私有区码**（番茄式字体加密） | `pua` 高 | 否，源站加密 |
> | **拼音替换**（`sè`=色） | `latin` 高 | 否，源站替换 |
> | **编码错乱**（整章乱码） | `U+FFFD` 高 / 首行乱码 | 否，**抓取 bug，必须重抓** |
> | **错别字**（`名子`/`淡`代`谈`） | 人工判 | **是，作者问题，计入 W 维** |

### 2.4 取不到正文时的降级链（2026-10 实测，按此顺序，别乱试）

> 背景：为《民调局异闻录》在 7 个源上手工试错，全部失败后才发现真正的解法。固化下来避免重复踩。

```
正文取不到？
│
├─ ① 先跑 scripts\source_probe.py（自动分类 + 自动UA降级）
│     它会给出七类判定，不用你手工看字数、猜是不是拦截页
│
├─ ② 若判 EMPTY_SITE（页面含「转码失败」）
│     → 站点自身无内容。换源。爬虫去了也没用。（实测遇到过这类站点）
│
├─ ③ 若判 CF_BLOCK / BLOCKED / SHELL
│     → source_probe 会自动换移动UA再试，
│       实测同一章节页：PC UA → 403、移动UA → 200。
│       ★ 这是性价比最高的一招，先于任何重型方案
│
├─ ④ 移动UA 也失败 → 跑 scripts\fetch_mobile_ua.py --try-all-ua
│     轮换 5 个移动 UA（iPhone/Android/微信/UC/夸克）
│
├─ ⑤ 仍失败 → 换索引，别硬刚（关键经验）
│     ★ 搜「书名 + 脱水版 / 已完结可M / 搬自天涯」→ 豆瓣小组 / 贴吧
│       实测：豆瓣小组一层就挖到 10 万字全文，绕过 7 个失败源
│
├─ ⑥ 再失败 → 上 tz-spider（skill name="tz-spider"）
│     L0 DrissionPage → L5 camoufox（需已安装）→ 报 camoufox_not_installed 就是缺依赖
│     ⚠️ camoufox 需 GitHub 下载，会遇 API 限流（60次/小时），可等重置或配 GITHUB_TOKEN
│
└─ ⑦ 全失败 → 标「无正文」，按用户指令：**模型自评 + 标注置信度低 + 写清卡在哪一步**
```

**实测记录（每一条都是踩出来的）**：

| 站点 | 现象 | 真实成因 | 正确处置 |
|---|---|---|---|
| 某备用源 | 页面正常、标题对，正文位写「转码失败」 | **站点自身无内容** | 换源，**别上爬虫** |
| daomuzw 章节页 | PC UA → 403（`403 Forbidden nginx`）；移动UA → **200，23024 字** | **Cloudflare WAF 按 UA 判定**，非 JS 挑战 | **换移动UA即可，不需要 camoufox** |
| daomuzw 目录页 | 一度 200，后 403 | 同上 | 同上 |
| panso.us | 404 | 站已挂 | 换源 |
| 豆瓣小组转载帖 | tz-spider 报 243 字 | 解析器不认 `.reply-doc.content` 结构 | **不代表没内容**，用 `source_probe` 复核（实测 10.6 万字） |

> **最重要的两条经验**：
> 1. **"403"不等于"要用 camoufox"**。先看响应体是 Cloudflare JS 挑战页（几十字 + "Just a moment"）还是 nginx 裸 403。**后者多半是 UA/WAF 规则，换 UA 就过。**
> 2. **换源常常比硬刚划算**。为《民调局》升级反爬武器前，先试试「书名+脱水版」搜 UGC 平台——那本书的全文我在豆瓣小组一层就找到了。

### 2.5 review-miner：采外部共识

- **多条目必须分口径**：豆瓣分卷/套装/再版**不可相加/平均/相减**；
- **短评均值 ≠ 官方评分**（五本里短评比官方低 0.8–1.0）；
- 优书网**单条星级是占位图**，只引聚合；
- **必做"烂尾"检索**；
- 每条标来源与强度（共识≥3/多数2/个别1）；
- **排除改编作品页面**（三次踩过）。

## 3. 实读阶段（三个 reader 并行）

**Lead 一次性 spawn 3 个**（本团队是扁平结构，teammate 不能再派下级）。

每个 reader 的 prompt **必须包含**：① 角色卡全文；② 自己的 seq 区间与 URL；
③ 输出格式；④ 收尾动作（落盘 + complete + send_message 给 lead）。

**统一跑量化工具**（别再让各人现写统计脚本——五本写过 4 遍重复的）：
```bash
python scripts/novel_stats.py reports\_body_<书名>_<区间>.json \
    --book <书名> --json-out reports\_stats_<书名>_<区间>.json \
    --crossbook reports\_crossbook_metrics.csv
```

---

## 4. 评价阶段（model-critic）

**顺序不可颠倒**：先自评落盘 → 再读外部共识对照。
**动笔前先读**角色卡里的「⚠️ 已知系统性偏差」六条（高估结局关注、低估反派批评、文笔偏宽容、把取舍当两件事、选择性报量化、抽样说成趋势）。

---

## 5. 汇总阶段（Lead）

套 `data\输出模板.md` 模板一。**Lead 不写文学评价**，只做：取证汇总、口径统一、交叉校验、过闸门。

**报告头固定写法**（时态必须诚实）：
```
> 防剧透：本报告已提交 spoiler-guard 审校（N 处越线表述已删改），定稿以审校后版本为准。
```
⚠️ **草稿阶段不得写"已过闸门"**——那时还没审（《大王饶命》就犯过，闸门判为"比剧透更该先改"）。

---

## 6. ⚙️ 程序闸门（v2.0 新增，送审前必跑）

```bash
python scripts\precheck.py reports\_draft_<书名>.md \
    --weights W=6.5,C=7.5,T=6.5,E=7.5,P=6.5,X=7.0 \
    --extra-words "<本书人名/地名词，逗号分隔>" \
    --strict
```

| 检查 | 内容 | 为什么必须程序化 |
|---|---|---|
| **C1 简介字数** | ≤120 且**自标值 = 实际值** | **4/4 本都在这里出错且全部少报** |
| C2 剧透扫描 | A0 正则 + 累积敏感词表 + 本书特化词 | 机械词能查的别让闸门查 |
| **C3 同句重复** | 危险表述出现 ≥2 次即报位置 | **连续 3 本被闸门抓出** |
| **C4 加权核算** | 六维加权精确值 vs 文中声称 | 曾出现 5.90 vs 实际 5.85 |
| C5 覆盖度算术 | 三段字数相加是否等于总数 | 算术错会直接毁掉覆盖度可信度 |
| C6 必备结构 | §0/§2/§3/§4/§5/§6/§9 + 标签 | 防止漏节 |
| **C7 不实陈述** | 草稿称"已过闸门"即 FAIL | 信任问题，优先级最高 |

**有 FAIL → 先改，别送审。** 这些错误零技术含量，不该占用审校往返。

## 7. 语义闸门（spoiler-guard）

跑完 precheck 再送。它能查的是程序查不了的：
- **语义级剧透**（换了说法说同一件事；包裹词泄露，如"信物+碎钻+价格"能锁定场景）；
- **同源重复**（换了措辞的同一处剧透）；
- **口径自相矛盾**（声明"不可相减"却在减）；
- **过度断言**（3.52% 覆盖说成"全书唯一"）；
- **证据标签缺失**、**空话**。

**它出 PASS 后我重跑 `precheck.py --mode final`**，确认改动没引入新问题。

## 8. 常见判定分歧的裁决原则（五本沉淀）

| 情形 | 裁决 |
|---|---|
| 评价"结局质量" vs 剧透"结局情节" | **前者允许**（读者知道"坑没填"只影响期待，推不出生死/配对）；**后者禁止**（谁死、谁复活、谁和谁在一起） |
| 战力批评（"19 发全中"） | **允许保留**——是可信度判断，且是 T 维证据；但**"终局反派被一刀解决"要泛化**（那是下场） |
| 作品有番外 | 番外可作**第二来源**补结局维度（《大王饶命》验证有效）；但涉及"代价被撤销"必须泛化措辞 |
| 读者给了分水岭坐标（"进入某地后崩了"） | 可保留**结构坐标**，但不要转述坐标之后发生了什么；模型可改写为机制描述 |
| 读者不评价结局 | 标"单一来源"，**不要据此推断"结局没问题"** |

## 9. 收尾

1. 最终报告落盘 `reports\<书名>_分析_<YYYYMMDD>.md`
2. 跨书基线追加：`reports\_crossbook_metrics.csv`（每本 3 行，按区间）
3. 若发现新的**站点级坑**（转码失败/章名错字/污染模式）→ **回写 `data\书源清单.md`**
4. 若发现新的**系统性偏差** → **回写对应角色卡的"已知偏差"章节**

## 10. 命名规范（v2.0 统一）

```
reports\
  <书名>_分析_<YYYYMMDD>.md          最终报告（无下划线前缀）
  _draft_<书名>_分析_<YYYYMMDD>.md   汇总草稿
  _scout_<书名>.md                   book-scout
  _catalog_<书名>.json               目录（**文件名必须含书名**）
  _review_<书名>.md                  review-miner
  _reader_<书名>_<early|mid|late>.md 三个 reader
  _body_<书名>_<early|mid|late>.json 正文
  _stats_<书名>_<区间>.json/.md      novel_stats 输出
  _critic_selfeval_<书名>.md         model-critic 自评
  _critic_final_<书名>.md            model-critic 定稿
  _guard_<书名>.md                   spoiler-guard
  _crossbook_metrics.csv             跨书基线（共用，追加）
```

⚠️ **一律带书名**。v1 时代第一本用的是 `_reader_early.md`（无书名），导致按文件名做横向对比时会**静默漏掉一本**——比报错更危险。
